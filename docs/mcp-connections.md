# MCP 连接管理

同一用户不能重复保存相同传输方式和完整 URL 的连接，新增或编辑冲突返回 HTTP 409；更换名称或禁用连接也不会绕过检查。不同用户可以各自保存同一服务。已有重复记录需手动删除多余项。

在工作台 `/mcp` 管理当前用户的服务器，支持 SSE 与 Streamable HTTP。列表、保存、启停、删除和检查均以服务器为事实来源，其他用户无权访问。检查会真实连接并显示实际发现的工具或安全错误码；没有预置假工具和假结果。

完整 URL（包括 query）会持久化并返回。**禁止把 token/secret 放进 URL query**。当前连接模型不支持自定义 headers。URL 必须使用 http/https、有 host、无 userinfo。不要在名称和工具描述中放入凭据。

超时范围为 1..300 秒，发现重试次数为 0..5，每次尝试均受超时限制。工具调用最多一次，不自动重试；调用超时后远端可能已经执行，需先确认远端状态。工具参数值、原始结果与异常不进入审计；审计只保留工具名、参数键、状态、耗时和固定安全摘要。

Chat 每个请求从当前用户的启用连接重新发现工具，发现缓存只用于展示；不同服务器或与内置工具同名会明确失败。禁用连接不参与 Chat。手动检查禁用记录仍会真实连接，用于排障。

仅当用户没有任何连接记录时，现有项目配置 `clsMcpServer.url` 才能作为真实回退来源（SSE、30 秒、不重试）。回退不生成用户 profile，也不掩盖配置错误或发现失败。新增一条禁用连接即可阻止回退。后续 AIOps 复用相同 owner-scoped provider。

官方 cls-mcp-server 在主机运行，启动与凭据细节由 P26 补充。真实 CLS smoke 必须独立连接官方服务；无配置、凭据或服务时明确未执行，单测 transport 替身与浏览器接口夹具不构成真实验收。
